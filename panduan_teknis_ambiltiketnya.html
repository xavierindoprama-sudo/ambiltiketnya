1. Ringkasan Eksekutif & Gambaran Proyek

AmbilTiketnya adalah platform manajemen tiket acara modern yang dirancang khusus untuk gereja, seminar, konser rohani, dan komunitas. Platform ini membebaskan penyelenggara dari biaya komisi pihak ketiga (*zero third-party ticketing fee*), menyediakan alur reservasi cepat, menerbitkan e-tiket resmi berformat PDF A4 ber-QR Code dengan Syarat & Ketentuan Kustom, serta menyediakan sistem check-in kamera berkelanjutan (*continuous scanner*) yang presisi dan cepat di pintu masuk (*gate entrance*).

1.1. Prinsip Utama Desain Sistem

  • Serverless & Zero Maintenance: Seluruh infrastruktur berjalan di edge network Cloudflare dan Neon Database serverless tanpa server fisik (VPS) yang perlu di-patch atau di-restart. Biaya operasional 100% efisien.
  • Offline Resilient (PWA): Berjalan sebagai Progressive Web App dengan Service Worker (sw.js). Petugas gerbang tetap dapat memindai tiket sekalipun sinyal internet venue sempat putus berkat modul sinkronisasi offline.
  • Viewfinder Precision Scanning: Kamera pemindai hanya mendeteksi kode QR yang berada tepat di dalam kotak bidik laser (mencegah pemindaian tidak sengaja dari sudut jauh).
  • Continuous Anti-Duplicate Lock: Mencegah tiket yang sama terpindai dua kali secara berurutan (*double check-in*) dengan mekanisme penahan 10 detik otomatis selama tiket masih terlihat di kamera.
  • Interactive Demographics: Dasbor analitik dengan kurva kedatangan check-in, diagram gelembung interaktif asal gereja, dan klasifikasi usia lengkap hingga lansia.

2. Cetak Biru Arsitektur Global (System Architecture)

Sistem AmbilTiketnya mengadopsi pola JAMstack + Edge Microservices yang memisahkan frontend statis dengan backend serverless compute dan database pooling.

• Resend API: Pengiriman email e-tiket & OTP • Google OAuth: Login satu klik (GSI) • WhatsApp Direct: Tautan instan wa.me

4. Alur Kerja Inti & Mekanisme Teknis (Core Workflows)

4.1. Alur Autentikasi Ganda: Native vs Google Sign-In

AmbilTiketnya mendukung dua metode autentikasi yang aman dan terpadu:

  1. Native Email & Password Hashing: Kata sandi diproses dengan algoritma Iterative Salted SHA-256 (1.500 putaran kriptografi). Format tersimpan: {iterasi}${salt}${hash}. Sistem memblokir akun sementara selama 15 menit jika terjadi 5 kali kegagalan login berturut-turut.
  2. Google Sign-In (OAuth 2.0 Identity Services): Frontend menginisialisasi Google One-Tap/Button SDK dengan Client ID 866753632616-opg57movh0h0th1av7b927d7fvrg3n6e.... Kredensial ID Token dikirim ke Cloudflare Worker untuk divalidasi ke endpoint Google (https://oauth2.googleapis.com/tokeninfo). Jika akun belum terdaftar, pengguna baru dibuat otomatis dan diarahkan untuk melengkapi nomor WhatsApp, usia, dan asal gereja.

4.2. Penerbitan E-Tiket PDF A4 & Syarat Ketentuan Kustom

Berbeda dari tiket gambar biasa, AmbilTiketnya menghasilkan dokumen PDF berformat resmi A4 beresolusi tinggi langsung di sisi klien (*client-side rendering*) via pustaka jsPDF (2.5.1):

  • Header Dokumen: Kop resmi, pita status (Valid / Belum Bayar), dan nomor pesanan unik.
  • Badge Status Kehadiran: Menampilkan jumlah jemaat, jenis tiket (Reguler, VIP Invitation, Walk-In), dan tanggal acara.
  • QR Code Verifikasi Gerbang: Dirender secara presisi berbasis matriks modul hitam pekat tajam tanpa distorsi pikselasi.
  • Syarat & Ketentuan Acara Kustom: Teks S&K yang diatur oleh Admin pada masing-masing acara dicetak rapi di bagian bawah tiket dengan pembungkusan teks otomatis (*word wrapping*), sehingga peserta memahami aturan spesifik acara (misal: pakaian bebas rapi, dilarang membawa makanan/minuman, batas jam gerbang ditutup).

4.3. Notifikasi Pengiriman Tiket Ganda (Email & WhatsApp)

📧 Notifikasi Email (Resend REST API)

Begitu tiket terbit atau pesanan dikonfirmasi admin, Cloudflare Worker memanggil Resend API dengan payload HTML responsif. Email berisi ringkasan acara, barcode tiket, dan tombol langsung menuju halaman e-tiket resmi.

💬 Notifikasi WhatsApp (Direct Link)

Platform menyusun pesan teks terformat rapi dan membuka tautan https://wa.me/{nomor}?text=... secara otomatis, mengarahkan peserta membuka tautan resmi https://ambiltiketnya.online/?tiket=TKT-... pada domain kustom.

4.4. Pemindai Kamera Berkelanjutan (*Continuous Camera Scanner*)

Fitur pemindai dirancang khusus untuk menangani antrean ribuan jemaat dalam waktu singkat di pintu masuk gerbang dengan performa tinggi dan nol kesalahan baca.

Mekanisme Presisi Viewfinder ROI (Mencegah Deteksi di Luar Kotak):
Secara default, algoritma kamera mendeteksi seluruh bidang tangkapan lensa (*full sensor*), sehingga tiket yang masih berada di sudut/pinggir layar dapat langsung terbaca sebelum tamu siap. AmbilTiketnya mengatasi masalah ini dengan memproyeksikan koordinat CSS kotak bidik (#sc_frame) ke koordinat piksel video murni menggunakan fungsi getFrameRoi(). Jika titik tengah kode QR berada di luar kotak bidik laser, pembacaan seketika diabaikan hingga QR diarahkan tepat ke dalam kotak.
Pencegahan Rescan Berulang (10-Second Silent Anti-Duplicate Lock):
Bila seorang tamu menyodorkan tiketnya, tiket akan diverifikasi seketika (hijau & suara nada naik). Selama tiket yang sama masih dipegang di depan lensa kamera, timer penahan akan terus di-reset secara otomatis tanpa bunyi error (*silent suppression*). Tiket yang sama tidak akan pernah terscan ulang secara tidak sengaja hingga tiket dijauhkan dari lensa selama lebih dari 10 detik. Namun, bila tamu berikutnya menyodorkan tiket baru yang berbeda, pemindai langsung membacanya seketika dalam 1,5 detik!

6.2. Alur Deployment Otomatis (CI/CD)

  1. Frontend (Cloudflare Pages): Setiap perubahan yang di-commit dan di-push ke branch main di repositori GitHub (xavierindoprama-sudo/ambiltiketnya) akan secara otomatis memicu build dan deploy instan di Cloudflare Pages dalam waktu ~15 detik. Custom domain https://ambiltiketnya.online otomatis terbarui.
  2. Service Worker Cache Bumping (Penting!): Jika Anda memperbarui file frontend (index.html, scan.html, atau config.js), pastikan untuk menaikkan versi konstanta cache di sw.js (contoh: dari atk-v34 menjadi atk-v35). Hal ini memaksa browser pengguna dan PWA membersihkan cache lama dan mengambil aset terbaru seketika.
  3. Backend (Cloudflare Worker): Jika Anda mengubah file cloudflare-worker/worker.js, Anda dapat mem-paste kodenya ke editor Cloudflare Dashboard Worker atau menggunakan command line Wrangler: 
    npx wrangler deploy cloudflare-worker/worker.js --name ambiltiketnya-api
  4. Migrasi Database (Neon SQL): Bila ada penambahan kolom/tabel baru, buka Neon Console → SQL Editor dan jalankan skrip migrasi terkait (seperti migrate-walkin.sql atau migrate-oauth.sql).

7. Panduan Pemecahan Masalah (Troubleshooting & FAQ)

Gejala Masalah Kemungkinan Penyebab Solusi Cepat
Kamera scanner hitam atau izin ditolak di HP. Browser memblokir izin kamera atau situs belum menggunakan HTTPS. Pastikan URL dibuka via https://ambiltiketnya.online. Buka pengaturan browser smartphone → Izin Situs → Izinkan Kamera.
Email konfirmasi e-tiket tidak sampai ke tamu. Kuota harian akun Resend habis atau email masuk ke folder Spam/Promotions. Periksa log di dashboard Resend.com. Minta jemaat memeriksa folder Spam atau gunakan tombol alternatif Buka WhatsApp untuk mengirim link tiket via WA.
Tombol atau tampilan di HP masih versi lama. Service worker atau browser menyimpan cache versi sebelumnya. Lakukan Hard Refresh (Ctrl+F5) atau tutup tab dan buka kembali. Pastikan versi cache di sw.js sudah dinaikkan saat deploy.
Akun Admin terkunci (*Locked Account*). Gagal memasukkan password lebih dari 5 kali berturut-turut. Tunggu 15 menit hingga kunci akun terbuka otomatis, atau gunakan menu Lupa Password untuk verifikasi kode OTP ke email.
